Root Cause (two compounding bugs)
1. Silent auth failure — bcrypt/passlib version mismatch (the actual "Invalid email or password" bug)
requirements.txt had bcrypt unpinned, which resolves to bcrypt 5.0.0. passlib==1.7.4 (last release, 2020) detects the bcrypt backend via bcrypt.__about__.__version__, an attribute that bcrypt removed in 4.1+. I reproduced this directly: both hash_password() and verify_password() in auth/utils.py raise a ValueError, they don't return False. Since router.py doesn't catch that exception, FastAPI returns a generic 500 with no JSON detail field. Your Login.tsx (line 29) falls back to the string 'Invalid email or password' whenever err.response?.data?.detail isn't a string — so a server crash was being displayed as a wrong-password message. This affected every login attempt, valid or not.

2. database.py was never connecting to MongoDB Atlas at all
It imported and used mongomock_motor.AsyncMongoMockClient() — an in-memory mock — and never read settings.MONGODB_URI. AsyncIOMotorClient (the real driver) was imported but unused. This is presumably leftover test scaffolding that never got swapped back. Your app was running entirely on ephemeral in-process data, disconnected from your real Atlas cluster/collections.
